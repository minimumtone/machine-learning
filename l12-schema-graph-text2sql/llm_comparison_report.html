4.3 LLM モードの利点

  • 数値条件の生成：Rule-based では不可能な「band gap > 1.0 eV」のような 数値比較 WHERE 句を LLM は生成できる可能性がある。
  • 自由文への対応力：辞書に未登録の表現でも、LLM は文脈から 意図を推定して適切な SQL を生成できる場合がある。
  • Few-Shot の効果：類似の成功事例がプロンプトに注入されることで、 スキーマリンクの精度が向上する。

4.4 LLM モードのリスク

  • ハルシネーション：存在しないテーブル名やカラム名を生成する可能性がある。 Schema 制約でプロンプトに許可テーブル/カラムを明示しているが、完全には防げない。
  • SQL構文エラー：LLM が生成した SQL が PostgreSQL の構文として不正な場合がある。 SQL Guard で検証し、repair_loop で修復を試みるが、修復に失敗するケースもある。
  • レイテンシ：Rule-based の <100ms に対し、LLM は数秒〜数十秒かかる。 インタラクティブな利用には不向きな場合がある。
  • コスト：API 呼び出しごとに課金が発生する。大量クエリの場合はコスト管理が必要。
  • セキュリティ：ユーザーのクエリ内容が外部 API に送信される。 機密データを含むクエリには不適切。
